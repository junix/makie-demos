项目概述

MakieDemos 是一个演示型 Julia 包，专注于展示 CairoMakie 的高级可视化能力。 它包含 12 个精心调校的场景，覆盖 2D、3D、统计、流场、矩阵、分子、极坐标、时间线、拓扑和多面板组合等多种图表类型。

与普通示例库不同的是，MakieDemos 强调「出版级质量」：统一的设计语言（自定义主题系统）、固定的画布尺寸（1600×1000）、 透明背景（便于嵌入幻灯片和文档），以及自动化的像素级质量验证。

所有数据均为确定性合成数据——不需要外部数据源，每个 demo 函数内部生成其数据，使项目完全自包含、可复现。

分层架构

MakieDemos 采用清晰的四层结构：最上层是调用入口（脚本与测试）， 中间是领域层（MakieDemos 模块，承载主题、场景构造、渲染与验证）， 再下层是Makie 生态（场景图 + Cairo 后端），最底层是产物层（PNG + JSON）。

关键设计原则是「场景函数纯净」——每个 demo 函数只返回一个 Figure 对象，不负责保存、验证或元数据生成。 这些横切关注点由 render_demo 统一编排，保证 12 个场景函数保持高度一致的接口。

渲染流水线

单个 demo 的渲染过程是一条线性流水线，由 render_demo 函数编排。 从主题应用开始，经过场景构造、PNG 保存、像素验证，最终产出 manifest JSON。 任何一步失败都会抛出异常，保证不会有半残产物混入输出目录。

流水线的关键洞察是「验证即质检」：validate_png 不是可选步骤，而是渲染流程的一部分。 它通过三个阈值（透明像素 ≥18%、可见像素 ≥10000、彩色像素 ≥3000）确保输出符合出版级标准。

我们选择「渲染地形曲面」（surface-terrain）作为端到端走查场景。 这是 12 个 demo 中最具代表性的 3D 示例，涉及主题系统、数据生成、3D 坐标轴、多重 plot 叠加、Colorbar 和像素验证全链路。

启动渲染脚本

用户在项目根目录执行 julia --project=. scripts/render.jl。Julia 加载 Project.toml 环境，预编译 MakieDemos 模块及其依赖（CairoMakie、JSON3、Statistics）。

遍历 DEMOS 字典

render_all 读取常量字典 DEMOS 中的 12 个 key，按字典序排列后逐一调用 render_demo(name, output_dir)。每个 demo 独立渲染，互不影响。

构造场景图

以 surface-terrain 为例：先 apply_theme! 设置全局主题（字体、颜色、透明背景），再调用 surface_terrain()——生成 190×155 的网格数据，创建 Axis3 3D 坐标轴，叠加 surface（曲面）和 wireframe（线框），最后添加 Colorbar。返回 Figure 对象。

保存并验证 PNG

调用 CairoMakie 的 save 将 Figure 渲染为 1600×1000 PNG 文件。紧接着执行 validate_png：逐像素统计透明、可见、彩色像素数，与阈值比较。不通过则抛出异常，中断整个渲染流程。

写入 manifest JSON

验证通过后，将尺寸、像素统计、渲染耗时、后端类型等信息组装为字典，通过 JSON3 序列化为同名 .json 文件，与 PNG 并排放置在输出目录中。

模块详解

主题系统

主题系统是 MakieDemos 视觉一致性的基石。通过一组常量颜色（INK 深墨色、MUTED 辅助灰、ACCENT 强调红、PALETTE 四色调色板） 和 apply_theme! 函数，统一设置 Figure、Axis、Colorbar 等所有 Makie 块的默认样式。

值得注意的设计选择是透明背景优先：Figure 和 Axis 的背景色均设为 :transparent， 这意味着生成的 PNG 可以直接叠加在任何背景上（幻灯片、文档、网页），无需额外抠图。

header! 是另一个复用组件——它为每个图添加三段式标题（kicker + title + subtitle）， 确保 12 个 demo 拥有统一的页眉版式。

场景构造函数

12 个场景构造函数遵循同一约定：零参数、返回 Figure 对象、内部生成所有数据。 这种「纯净函数」设计使得场景可以被任何上下文复用——CairoMakie 保存为位图，GLMakie 打开交互窗口， 或者嵌入到更大的布局中。

渲染与验证

render_demo 是整个项目的编排核心。它串联主题应用、场景构造、文件保存、质量验证和元数据输出。 而 render_all 只是对 render_demo 的简单映射。

validate_png 采用「像素三阈值」策略：

  • 透明像素 ≥ 18%：确保背景确实透明，而非意外填充了白色。
  • 可见像素 ≥ 10,000：确保图像不是空的或几乎空白。
  • 彩色像素 ≥ 3,000：确保有实际的图表内容（灰度差 > 0.10）。

这是一种轻量但有效的「冒烟测试」——不验证内容正确性，但能捕获 90% 的渲染故障（空白图、全黑图、背景不透明等）。

目录与元数据

catalog.json 是项目的「目录卡」，为每个 demo 提供结构化元数据： id（唯一标识）、use（用途描述）、family（所属家族）、 question（该图回答的问题）、complexity（复杂度）和 tags（标签数组）。

这种设计使项目不仅是代码集合，更是可检索的可视化模式库。下游工具可以通过解析 catalog.json 实现搜索、筛选、按家族分组展示等功能，而无需解析 Julia 源码。

值得注意的是，catalog.json 与 DEMOS 字典是双源冗余的——demo 列表同时存在于 Julia 代码和 JSON 文件中。 这是有意为之：代码面向运行时，JSON 面向工具链和静态站点生成，两者通过测试中的数量断言（≥12 个）保持同步。

质量保障

MakieDemos 的质量保障体系由三层防线构成：渲染时验证（validate_png）、 测试时断言（runtests.jl）和目录同步（catalog.json 数量校验）。

测试套件在临时目录中全量渲染 12 个 demo，然后逐一断言：宽度 = 1600、高度 = 1000、 透明像素 > 280,000（约 17.5%，略低于代码内 18% 阈值，留误差余量）、 可见像素 > 10,000，以及对应的 JSON manifest 文件存在。

这种「端到端像素测试」比单元测试更有意义——可视化代码的 bug 往往不体现在函数返回值上， 而体现在输出图像的视觉缺陷上。通过量化像素统计，可以在不做图像比对的情况下捕获大部分故障。

构建与发布

项目使用 just 作为统一构建入口，justfile 提供三个 recipe：

  • just render：运行渲染脚本，生成所有 PNG 和 JSON 到 out/ 目录。
  • just test：运行 Julia 测试套件，执行端到端像素级验证。
  • just instantiate：实例化并预编译所有依赖，用于首次设置或 CI 缓存预热。

依赖管理通过 Julia 的标准 Project.toml + Manifest.toml 机制实现， 确保可复现的环境。核心依赖只有四个：CairoMakie（渲染后端）、GLMakie（可选交互后端）、 JSON3（清单序列化）和 Statistics（统计计算）。

作为演示项目，MakieDemos 不发布到 Julia 注册表，也不安装到系统路径。 它的「产物」就是 out/ 目录下的 PNG 和 JSON 文件，可以直接嵌入文档、上传到静态站点， 或作为其他可视化项目的参考实现。
